# Дополнение: сборщик базы прошивок (дешёвая LLM вместо Claude)

Цель: наполнять `data/devices/` сотнями моделей автоматически, не тратя лимиты Claude. Тяжёлую рутину делает скрипт + DeepSeek API, Claude Code только пишет сам скрипт.

## Главное правило

LLM **не придумывает** факты о прошивках. Источник фактов — открытые структурированные списки устройств на GitHub. DeepSeek только **нормализует и сводит** найденное в нашу JSON-схему. Нет данных в источнике → поле `unknown`.

## Источники (сначала проверить, что актуальны и доступны)

- LineageOS: репозиторий вики, папка с YAML-файлами устройств (`_data/devices`).
- Официальные списки устройств крупных проектов прошивок, у которых есть device-list в открытом репо или JSON для OTA (crDroid, PixelOS, Evolution X, LMODroid, iodéOS, /e/OS и т.п. — что найдётся).
- TWRP: репозиторий сайта со списком устройств.
- OrangeFox: публичный список устройств.
- Списки Treble/GSI-совместимости, где они есть в открытом виде.

Для каждого источника — отдельный модуль-парсер. Брать только факты: кодовое имя, название, версия Android, официальность, статус поддержки, ссылка на страницу. Тексты инструкций не копировать.

## Скрипт `tools/collector/`

- Python 3, запуск: `python -m collector --sources all --limit 200`.
- Шаги:
  1. Скачать списки из источников (с кешем на диске, вежливые паузы, User-Agent проекта без личных данных).
  2. Свести по `codename` в черновики.
  3. Отправить черновик в DeepSeek для нормализации: склеить дубли названий, привести поля к `data/schema.json`, расставить `status`. В промпте модели жёстко: «используй только переданные данные, не добавляй ничего от себя, неизвестное = unknown, ответ — только JSON по схеме».
  4. Провалидировать ответ по схеме. Невалидно → повтор 1 раз → иначе в `collector/failed/`.
  5. Сравнить с уже существующим файлом модели: новое добавить, ручные правки людей (поле `manual: true` или отдельный `overrides/`) **никогда не перезаписывать**.
  6. Записать в `data/devices/`, обновить `index.json`.
- Вывод в конце: сколько моделей добавлено/обновлено/упало, сколько ушло токенов и примерная стоимость.
- Разблокировку загрузчика LLM не определяет: это поле только из проверенных источников или руками.

## DeepSeek API

- API совместим с OpenAI: базовый URL `https://api.deepseek.com`, модель `deepseek-chat` (проверь актуальные имя модели и цены в документации DeepSeek перед запуском).
- Ключ только из переменной окружения `DEEPSEEK_API_KEY` / GitHub Secret. В репозиторий не коммитить, в `.gitignore` — `.env`.
- Батчами по 10–20 моделей на запрос, `temperature: 0`, JSON-режим ответа.
- Флаг `--provider` чтобы при желании переключить на другую совместимую модель (OpenRouter, локальная через Ollama).
- Флаг `--dry-run`: всё делает, но не пишет файлы, показывает diff.

## Автозапуск

- GitHub Actions по расписанию раз в неделю: запускает сборщик и открывает **Pull Request** с изменениями (не пушит в main напрямую). Человек смотрит diff и мержит.
- В описании PR — сводка: новые модели, изменённые прошивки, ошибки.

## Счётчик

- В веб-версии и APK на главной: «В базе N моделей · M прошивок · обновлено <дата>», считается из `index.json`.
- Отдельная страница «Статистика»: сколько моделей по брендам, сколько активных прошивок, топ прошивок по числу устройств.

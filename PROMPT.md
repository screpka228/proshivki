# Задача для Claude Code: «Прошивки» — помощник по кастомным прошивкам

Сделай проект из трёх частей: **база данных**, **веб-версия** и **Android APK**.
Пользователь вводит модель (или APK сам определяет телефон) и видит: можно ли разблокировать загрузчик, есть ли рекавери, какие кастомные прошивки есть, ссылки на ветки 4PDA и XDA, сложность.

Дизайн — HTML-макеты в `design/` (открываются в браузере): `Home.html`, `Device.html`, `Contribute.html`. Повтори стиль точно в обеих версиях. Тёмная тема по умолчанию + светлая, переключатель — квадратная кнопка 44×44, радиус 12, справа сверху (☀ на тёмной, ☾ на светлой).

## 1. База (`/data`)

- Один файл на модель: `data/devices/<codename>.json`. Плюс сгенерированный общий `data/index.json` (скрипт сборки).
- JSON Schema в `data/schema.json`, валидация в CI на каждый PR.
- Поля: `codename`, `names[]` (маркетинговые имена и региональные варианты), `brand`, `soc`, `android_range`, `bootloader` { `status`: `open` | `oem_unlock` | `wait` | `impossible` | `unknown`, `wait_days`, `method`, `guide_url`, `notes` }, `recovery[]` { `name`, `official`, `url` }, `roms[]` { `name`, `android`, `status`: `active` | `abandoned`, `official`, `url` }, `treble_gsi` (bool), `difficulty` 1–5, `links` { `4pda`, `xda` }, `updated` (дата), `sources[]`.
- **Только ссылки и короткие факты своими словами.** Не копировать тексты, инструкции и картинки с 4PDA, XDA и других сайтов.
- Стартовое наполнение: 30–50 популярных моделей (Xiaomi / Redmi / POCO, Samsung, Pixel, OnePlus, Motorola, Huawei как пример «нельзя»). Каждое поле, в котором не уверен, — `unknown`, ничего не выдумывать. Ссылки проверять, что они открываются.
- Шаблон Issue «Добавить / исправить модель» (GitHub Issue Forms) с полями как в `Contribute.html`.

## 2. Веб-версия (`/web`)

- Статический сайт без сервера, деплой на **GitHub Pages** через Actions.
- Грузит `index.json`, быстрый нечёткий поиск по имени и кодовому имени (в т.ч. по кириллице/опечаткам).
- Экраны: главная (поиск + популярное), карточка модели, «не нашли модель» → кнопка открывает предзаполненный GitHub Issue.
- Адаптив: на телефоне выглядит как макет, на ПК — по центру с max-width.
- Без трекеров и сторонних CDN.

## 3. Android APK (`/android`)

- Kotlin + Jetpack Compose, minSdk 26.
- При запуске сам определяет телефон (`Build.DEVICE`, `Build.PRODUCT`, `Build.MODEL`) и показывает карточку «Этот телефон» сверху, если модель есть в базе.
- Показывает текущий статус загрузчика этого телефона, если удаётся определить (`ro.boot.verifiedbootstate`, `ro.boot.flash.locked` и т.п.). Root не требуется.
- База скачивается с GitHub (raw `index.json`), кешируется, работает офлайн. Кнопка «Обновить базу». Встроенная копия базы в APK на случай первого запуска без сети.
- Ссылки открываются во внешнем браузере.
- GitHub Actions: подписанный release APK, ключ из GitHub Secrets (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`), keystore не коммитить, один ключ для всех версий. APK прикладывать к GitHub Releases.

## Фото телефона на карточке

- У модели поле `image` { `url`, `author`, `license`, `source` }. На карточке модели — фото слева от названия, в списках — маленькая миниатюра (см. макеты на холсте).
- Брать **только фото со свободной лицензией**: Wikimedia Commons (CC BY / CC BY-SA / PD) или присланные сообществом через Issue с согласием на CC BY-SA. Подпись автора и лицензии показывать под фото.
- **Не брать** рендеры и фото с сайтов производителей, GSMArena, магазинов и 4PDA — они защищены авторским правом. Не хотлинкать чужие сайты.
- Фото хранить в репо (`data/images/<codename>.webp`, до 600 px по высоте) или по прямой ссылке на Commons.
- Нет фото — нейтральный силуэт телефона (SVG), как в макете.
